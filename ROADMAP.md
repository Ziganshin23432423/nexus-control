# NEXUS CONTROL — ROADMAP

Windows first. Cross-platform architecture. Linux later.

## Согласованный MVP

Продолжать согласованные этапы из [README](./README.md#следующие-этапы): локальное хранение компьютеров, проверки доступности, стандартные Windows-клиенты, Wake-on-LAN и сборка Windows-приложения. Будущие возможности не расширяют текущий этап.

## После MVP: Automations / Scripts

Отдельный будущий модуль для сценариев, которые пользователь создаёт для своих компьютеров или устройств, на управление которыми у него есть разрешение.

Предварительно рассматриваются два уровня:

1. **Визуальные автоматизации** из безопасных, разрешённых действий NEXUS. Пример будущего сценария: Wake-on-LAN → ждать SSH → выполнить разрешённое действие → запустить программу → открыть RDP.
2. **Advanced scripts** для опытных пользователей: PowerShell на Windows; Bash после отдельного этапа полноценной поддержки Linux.

Обязательные будущие принципы: сценарий создаёт пользователь; запуск явный; целевой компьютер виден; действия выполняются с соответствующими разрешениями; есть журнал и отмена; скрытого исполнения нет; секреты не хранятся открытым текстом.

## Граница этапа 3

На этапе 3 не реализовывать scripts, произвольное выполнение команд, script IPC, PowerShell execution, scheduler или remote execution. Этот пункт ROADMAP не разрешает запуск команд сейчас.

Хранение компьютеров, общие сервисы и platform/provider abstraction сохраняют свои границы и возможность добавления отдельного модуля позже. Поля scripts, engine hooks, UI автоматизаций и детали Automation Engine сейчас не добавлять. Подробное проектирование и реализация потребуют отдельного запроса пользователя.
